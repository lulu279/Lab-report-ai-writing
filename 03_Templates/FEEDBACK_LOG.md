# 模板：反馈记录（FEEDBACK_LOG）

> 每次人工修改 AI 产出后记录。只有“可推广且经确认”的偏好才写入全局规范；一次性要求留在本任务记录。

```text
# 反馈记录：<日期> <任务>

## 1. 上下文
- 项目/任务：
- AI 产出文件/版本：
- 人工修改后的文件/版本：
- 修改范围：数值 / 结构 / 语言 / 图表 / 格式 / 文件

## 2. 修改明细

| # | 位置 | AI 原文/做法 | 人工改为 | 原因 | 类型 |
|---|---|---|---|---|---|
| 1 | | | | | 事实/计算/逻辑/风格/格式/合规 |

## 3. 原因分析

- 是数据/计算错误，还是表达偏好？
- 是本次特例，还是稳定习惯？
- 是否与已有规范冲突？
- 是否因为输入缺失/模板不清？

## 4. 是否可推广

- 可推广：是 / 否 / 待确认
- 适用范围：本任务 / 本课程 / 所有实验报告 / 所有写作
- 建议更新：
  - [ ] `STYLE_PROFILE.md`
  - [ ] `FORMAT_PROFILE.md`
  - [ ] `SCIENTIFIC_INTEGRITY.md`
  - [ ] `SOURCE_POLICY.md`
  - [ ] 工作流：
  - [ ] 模板：
  - [ ] 不更新，仅记录

## 5. 验证

- 修改后是否重新渲染/计算/检查？
- 是否影响其他图表/数值/章节？
- 是否需要回归测试？

## 6. 结论

- 一句话规则（可执行）：
- 反例（什么情况下不适用）：
- 下次检查方式：
```

## 记录规则

- 一次只记录一个可执行规则；不要写“写得更专业”这种无法检查的要求。
- 事实/计算错误优先于风格偏好；不要用风格调整掩盖数据问题。
- 同一偏好出现 2–3 次再考虑升级为全局规范；单次要求不污染全局。
- 规则变更同步 `CHANGELOG.md`。
