# 工作流：实验报告（EXPERIMENT_REPORT）

版本：1.2（2026-10-26）
适用：高分子物理实验及同类理工科实验报告。
默认输出：DOCX 报告 + PDF 预览（由 Word/WPS 从最终 DOCX 导出）+ XLSX 数据与图表 +（如要求）Origin 工程/脚本 + 图片源文件 + 交付说明。
本版新增：冷启动输入包（`00_START/INPUT_PACK.md`）、封面字段（`00_START/COVER_FIELDS.md`）、首次起草（`FIRST_DRAFT.md`）、报告生成器（`build_report_docx.py`）、旧数值污染检查（`check_contamination.sh`）。

## 0. 先识别任务类型

满足以下任一条件即走本工作流：

- 有实验讲义/指导书 + 原始数据 + 报告模板；
- 要求“写实验报告/处理数据/画图/拟合/交付 Word/Excel/Origin”；
- 课程作业、实验总结、测试报告。

不适用：文献综述（走 `LITERATURE_REVIEW.md`）、原创论文（走 `RESEARCH_PAPER.md`）、纯数据分析无论文（可复用本工作流第 3–5 步）。

先填 `00_START/INPUT_PACK.md` 和 `00_START/COVER_FIELDS.md`；下面是压缩版清单。

```text

实验日期：
交付格式与截止：
原始数据（DATA）：

  - 数据列含义/单位：
  - 样品/分组/测试条件：
格式参考（FORMAT）：
  - 课程模板：
  - 往届排版/图表范例：
内容参考（CONTENT）：
  - 讲义章节：
  - 教材/文献：
教程/清单：
已知缺失/待核：
是否允许 AI 辅助/需否声明：
封面四项（班级/姓名/学号/实验内容）：
```

硬性检查：

- [ ] 课程是否禁止完全 AI 写作？本课程禁止；AI 只能辅助。见 `01_Governance/HUMAN_IN_THE_LOOP.md`。
- [ ] 首页是否要求班级/姓名/学号/实验内容？本课程要求，缺一即 0 分；填 `00_START/COVER_FIELDS.md`。
- [ ] 原始数据是否只读备份？
- [ ] 是否有数据列说明？没有则先问，不猜。
- [ ] 是否有多个版本的要求？以最后一次为准。

## 2. 推荐流程（10 步）

### 第 1 步：解析任务要求、讲义、数据和模板

- 读课程讲义对应实验章节，提取：目的、原理、步骤、结果要求、思考题。
- 读模板，记录：页面、字体、标题层级、图表注、参考文献格式。
- 读原始数据，记录：文件数、列名、单位、点数、异常/空值、测试条件。
- 读参考报告，只提取写法与结构，不提取本次数据/结论。
- 产出：`TASK_BRIEF.md`（用 `03_Templates/TASK_BRIEF.md`）。

### 第 2 步：建立输入清单，确认样品、分组、单位和列含义

- 每个样品一行：编号、名称、状态、测试条件、数据文件、备注。
- 每列一行：列名、物理量、单位、数据类型、是否用于拟合。
- 不确定的列先问；不要用“看起来像”推断。
- 产出：`INPUT_MANIFEST.md` 或在项目状态中记录。

### 第 3 步：复制原始数据到只读备份，记录处理步骤

```text
raw/                 # 原始文件，只读
raw_backup/          # 处理前副本（可选）
processed/           # 清洗/换算后的 CSV
scripts/             # 处理、绘图、建表、建文档脚本
figures/             # PNG/SVG
report/              # DOCX/PDF
delivery/            # 最终交付副本
```

- 不覆盖原始文件；脚本只写 `processed/`、`figures/`、`report/`。
- 记录脚本参数：平滑窗口、基线区间、积分窗口、拟合范围、排除点。
- 用时间戳或版本号区分重跑结果；旧结果进 `99_Archive/`。

### 第 4 步：数据清洗、计算、拟合与合理性检查

必做：

- 列对齐、单位统一、空值/重复/超量程检查。
- 原始、处理、拟合结果分表保存。
- 计算列保留公式或脚本；不把结果替换成静态值。
- 至少一种独立复核（Excel vs Python；直接计算 vs 拟合；手工抽查）。
- 拟合前说明：自变量、因变量、范围、权重、截距、排除点。
- 拟合结果给：方程、参数±标准误、R²、调整 R²、n、残差/系统偏差。
- 不只看 R²；检查残差趋势、异常点、参数物理意义。

按实验类型的专项检查：

| 实验 | 关键检查 |
|---|---|
| 光致荧光（PL） | 激发/发射谱区分；激发波长在吸收带内；归一化方式；QY 积分窗口、空白、内滤/再吸收；发射峰位不随激发波长改变（Kasha） |
| 红外（IR） | 透射率→吸光度 `A=−log10(T/100)`；横轴反向 4000→400 cm⁻¹；基线/大气水汽/CO₂；峰位±8 cm⁻¹ 归属；饱和带不参与定量；制样厚度差异 |
| 紫外（UV-Vis） | 空白与比色皿方向；A 落在 0.1–1.5；高浓度截顶/红移；光程换算；Beer-Lambert 线性范围；重复性 |
| TGA | Ts 为横坐标；TG/DTG 双轴；切线法基线区间；升温程序分段；样品量/装样；5% 失重与外推 Td 的区别 |
| DSC | 吸热方向；基线/锚带；峰温；ΔH=积分面积/(β·m)；结晶度 ΔH/ΔHf⁰；Tg 中线法；热历史（两次升温） |
| NMR | 相位、基线、溶剂定标（CDCl₃ 7.26、DMSO-d₆ 2.50、D₂O 4.79）；积分归一；多重峰/J；可交换氢；溶剂效应；浓度/溶解度 |
| GPC | 基线、积分区间、切割/切片；标定曲线；Mn/Mw/Mz/分散系数；RI 面积分数近似质量分数；低分子量峰；相对法限制 |
| 偏光显微镜（POM） | 正交偏光；黑十字；比例尺；同组放大倍率；球晶直径/半径测量；成核密度与生长速率；照片不得过度裁剪 |

### 第 5 步：生成图表和可编辑源文件

> 当前宿主没有可用绘图库；图的来源与降级方案见 `05_Tools/FIGURES.md`。AI 不能出图时，交 `figures/*.csv` + `plot_spec.md`，由用户在 Origin/Excel 导出 PNG；不要伪造图。

- 先定图的数据源与处理，再调样式；不要用示意图。
- 每张图一个脚本函数/一个 Origin 图页；文件名含图号与内容。
- 图内文字、图例、坐标轴、单位、四边框、线宽按 `FORMAT_PROFILE.md`。
- 同时输出 PNG（≥300 dpi）与 SVG/EMF（如需要）。
- 图注数值与表/正文一致；生成后抽查像素尺寸与文字是否被裁切。

### 第 6 步：按实验目标组织结果与讨论

> 没有初稿：先按 `FIRST_DRAFT.md` 起草。已有初稿：先过一遍 `REVISION_WORKFLOW.md` 的“论证遍”。不要先写段落再想论证。

推荐结构（课程要求 5 部分，可在不删内容的前提下扩展）：

```text
封面（班级/姓名/学号/实验内容/组别/日期）
摘要（可选，150–250 字）
1 引言
2 实验部分
  2.1 实验目的
  2.2 实验原理
  2.3 仪器与样品
  2.4 实验步骤
  2.5 数据处理（可选）
3 数据与结果
  3.1 … 3.n（按样品/现象/参数分节）
4 结果与讨论
  4.1 … 4.n（结构/条件/机理/误差）
5 思考题
6 结论
参考文献
附录（数据文件选择、补充图表、脚本说明）
```

- 课程只要求“目的/原理/步骤/结果分析与讨论/思考题”，上述扩展不得缺这五项。
- 结果与讨论可以合并，但事实与解释要分开写。
- 每个图/表在正文至少引用一次；图号/表号连续。

### 第 7 步：交叉核对图表、正文数据和计算结果

建立核对表：

| 项目 | 图 | 表 | 正文 | Excel/脚本 | 一致？ |
|---|---|---|---|---|---|
| Tm/ΔH | 图 1 | 表 1 | 3.1 | results.json | |
| R²/斜率 | 图 2 | 表 3 | 3.2 | 拟合表 | |
| 排除点 | 图 2 | 表 2 | 4.1 | 处理表 | |

- 数值、单位、有效数字、样品名、条件全部对齐。
- 图注中的数值也要核对（常被忽略）。
- 发现不一致时，以原始数据+脚本为准，回溯修改所有出现处。

### 第 8 步：按原模板生成 DOCX

优先用包内生成器：

```bash
python3 05_Tools/build_report_docx.py report.md --out report.docx
# 需要官方模板 2.54 cm 边距时：
python3 05_Tools/build_report_docx.py report.md --out report.docx --margins template
# 封面字段不齐时只能生成草稿：
python3 05_Tools/build_report_docx.py report.md --out report_draft.docx --draft
```

- 模板：`03_Templates/COURSE_TEMPLATE.docx` 用于对照/手工套用；生成器默认按 `FORMAT_PROFILE` 默认版式（A4/宋体+Times/10.5 pt/1.5 倍/标准三线表/图注 9 pt），**不注入**模板的封面图/占位符。若课程强制按官方模板，生成后在 Word/WPS 套模板，或用 `--margins template` 匹配 2.54 cm 边距。
- 字体三层设置；标题/正文/题注/表格/页眉页脚全部显式。
- 图片嵌入而非链接；所有表格标准三线表（顶/底 1.5 pt、表头线 0.75 pt、无竖线/内横线）；跨页表重复表头。
- 图注与图同页；标题与下段同页；避免孤行。
- 生成后先做结构审计；再在 Word/WPS 打开、导出 PDF。**未导出就写“未渲染/未验证”，不要声称 PDF 已验收。**

### 第 9 步：检查分页、字体、图注、公式、引用和文件完整性

先跑自动审计：

```bash
python3 05_Tools/build_report_docx.py --audit report.docx
sh 05_Tools/check_contamination.sh report.docx
```

再按 `FORMAT_PROFILE.md` 第 5 节逐项验收：

- 封面四项信息；
- 页码、页眉；
- 标题编号连续；
- 图/表编号与引用；
- 标准三线表、单位、表头重复；
- 公式编号、上下标；
- 参考文献真实、格式统一；
- 图片清晰、无变形、比例尺；
- 无模板示例文字、无 TODO、无 `【待核】`/`【缺图】`/`FIG_PLACEHOLDER`、无悬空引用；
- DOCX 能打开；PDF 如已导出，逐页检查；
- 旧范例数值/样品名是否误用。

### 第 10 步：交付终稿及约定的源文件

最小交付：

```text
<实验名称>_<组别>_实验报告.docx
<实验名称>_<组别>_实验报告.pdf        # 未导出则不列，或标“未渲染”
<实验名称>_<组别>_数据与图表.xlsx
<实验名称>_<组别>_交付说明.md
figures/（PNG/SVG）
scripts/（处理、绘图、建文档）
raw/（原始数据，按隐私要求）
```

交付说明必须写：文件清单、方法、主要结果、排除数据、未记录/待核、实际验证范围、与旧版差异、学生贡献记录（见 `HUMAN_IN_THE_LOOP.md`）。

## 3. 一轮任务的操作指令

用 `03_Templates/ONE_TURN_PROMPTS.md` 的模板。核心顺序：

```text
识别任务类型 → 读全局规范 + 本工作流 → 检查输入完整性 →
选 1–3 个最相关范例 → 先分析/计算 → 再写作/排版 →
运行验证 → 交付文件 + 简短校验说明
```

不要重复询问已明确的信息；缺失信息是否提问按第 4 节判断。

## 4. 何时先提问

只有缺失信息会实质性改变以下内容时才先问：

- 科学结论（样品是什么、测试条件、峰归属）；
- 数据计算（列含义、单位、拟合范围、排除规则）；
- 文件结构（交付格式、模板、是否要 Origin）；
- 合规性（课程是否允许 AI、是否需要声明、封面信息）。

非关键缺失（室温、气压、无关紧要的外观描述）可以继续，但必须写“未记录/待核”，不得编造。

## 5. 常见失败与处理（来自本工作区）

| 失败 | 实际例子 | 处理 |
|---|---|---|
| 封面信息缺失 | 7 份成品只有标题，没有姓名/学号/班级 | 生成前填 `00_START/COVER_FIELDS.md`；生成器缺项会报错；渲染后检查首页 |
| 交付说明与文件不符 | IR 说明称 8 图 10 表/17 页；DOCX 实际 8 图/5 表，XLSX 原生图 7 张；页数待渲染。DSC 说明称 12 页，渲染 PDF 为 9 页 | 交付说明由脚本从最终文件统计生成；不手写页数；DOCX 图数与 XLSX 原生图数分开统计 |
| 旧图未替换 | DSC 说明要求手动“更改图片”，Word 内仍是旧图 | 重新生成 DOCX；或在交付前逐张核对图注与图 |
| 字体回退 | 主题字体导致 WPS 变等线 | 三层显式 + XML 审计 |
| 编号跳号 | TGA 3.1→3.2→3.5 | 标题自动编号 + 生成后扫描 |
| 结构缺失 | TGA 无结果表；POM 无汇总表 | 至少 1 张条件表 + 1 张结果表 |
| 纯文本误判 | GPC 的 10⁵ 上标在文本抽取中丢失 | 核对 Word 实际显示/`vertAlign`，不只看文本 |
| 数据与正文不一致 | DSC 图注 Tm 与表 1 必须逐项核对 | 建立核对表；图注也纳入核对 |
| 文件损坏 | DOCX 包内残留 `cover_xml.txt` | 清理非标准 part；重新打包并打开验证 |
| 只给图不给数据 | 早期报告只有 PNG | 每张图对应 Excel 工作表 + 脚本 |

## 6. 验收标准

按 `06_Evaluation/SCORECARD.md` 打分：

- 科学准确性、数据/计算正确性、来源真实性为硬指标；任一造假直接不合格。
- 格式/风格分不能抵消数据错误。
- 课程合规（封面、AI 使用）为提交阻断项。
- 交付完整性以最终文件核验为准，不以交付说明自述为准。

## 7. 最小可行版本（时间不够时）

1. 先保证：原始数据备份、列含义、关键计算、1–2 张核心图、结果/讨论/结论、封面信息。
2. 再补：完整图表、误差分析、思考题、参考文献、附录。
3. 最后：字体/分页/三线表/PDF 渲染。
4. 任何情况下不编造、不缺封面、不交打不开的文件。
