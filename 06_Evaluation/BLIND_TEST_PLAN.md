# 盲测与回归计划（BLIND_TEST_PLAN）

版本：1.1（2026-10-26）
目的：验证“规范 + 工作流 + 范例”能否在新任务中复现个人认可的结果，而不是只验证文字像不像。
v1.2 要求：盲测必须走 `02_Workflows/FIRST_DRAFT.md` → 四遍改稿 → `05_Tools/build_report_docx.py` → `07_Projects/高分子物理实验2026/SUBMISSION_CHECKLIST.md`；记录写入 `06_Evaluation/runs/`。
注意：下表“隐藏的终稿”是历史工作区文件，本包不含；找不到时用“评分人手中的历史成品”，不要从范例卡反推数值。

## 1. 测试原则

- **只给原始输入，不给终稿**；终稿由评分人保管。
- 同一模型、同一参数、同一时间窗；不同任务分开跑。
- 每类工作流至少 2 个任务；任务差异大时加测。
- 评分用 `SCORECARD.md`，先过诚信/合规门槛，再看 7 维。
- 不把“文字像”作为唯一标准；数据、结构、格式、可复现性同等重要。
- 每次只改 1–3 条规则，再复测；避免一次改太多无法归因。

## 2. 本课程的首轮盲测任务

| 轮次 | 任务 | 原始输入 | 隐藏的终稿 | 目的 |
|---|---|---|---|---|
| R1 | TGA | `TGA/raw_data/...` + 讲义 + 模板 | `TGA/TGA实验报告.docx` | 测 TG/DTG、切线法、结构讨论 |
| R2 | GPC | `GPC/g-1.xlsx` + 讲义 + 模板 | `GPC/GPC_实验报告.docx` | 测淋洗曲线→标定→分子量链 |
| R3（可选） | DSC | 原始 zip + 讲义 | `DSC/...docx` | 测积分/热历史/可编辑资产 |
| R4（可选） | UV-Vis | 原始 CSV（若找回）+ 讲义 | `UV-Vis/...修订版.docx` | 测拟合/排除/溯源 |

首轮选 TGA 与 GPC 的原因：两者都有完整原始数据与终稿，且任务差异大（热分析 vs 色谱），能暴露不同问题。

## 3. 单次盲测流程

```text
1. 冻结终稿：记录文件哈希/修改时间；评分人保存，不放入 AI 上下文。
2. 准备输入包：
   - 讲义对应章节；
   - 原始数据 + 数据说明；
   - 空白模板；
   - 本系统 01/02 规范与工作流；
   - 1 个范例卡（TGA 用 TGA_SILVER；GPC 用 GPC_SILVER）；
   - 明确的交付要求（DOCX/PDF/XLSX/图/交付说明）。
3. AI 执行：按 ONE_TURN_PROMPTS A 或 B。
4. 产出归档：`06_Evaluation/runs/<日期>_<任务>/`。
5. 评分人盲评：先看门槛，再按 7 维打分；记录证据。
6. 对照终稿：列出“结构/数值/图表/语言/格式”差异。
7. 归因：输入缺失？规范不清？范例误导？模型能力？
8. 改规则：每条差异转成可执行规则，写入对应文件；更新 CHANGELOG。
9. 复测：换另一个任务，确认修复没有引入新问题。
```

## 4. 评分与通过标准

| 项目 | 通过标准 |
|---|---|
| 门槛 A | 无造假、无伪造验证、封面四项齐全、AI 使用合规 |
| 门槛 B | DOCX/PDF 可打开；XLSX 可打开；图表编号/引用完整；交付说明与实际一致 |
| 科学准确性 | ≥4 |
| 数据/计算 | ≥4；关键数值与终稿一致或差异有合理解释 |
| 论证逻辑 | ≥4 |
| 风格 | ≥4 |
| 格式 | ≥4（首轮可 3.5，但需列出待修项） |
| 溯源 | ≥4 |
| 文件完整性 | ≥4 |
| 总分 | ≥26/35；且不得有 P0 阻断项 |

“关键数值一致”指：峰温/分子量/R²/斜率/积分结果等；允许因拟合窗口/有效数字不同产生小差异，但必须在交付说明中解释。

## 5. 差异分类与归因

| 差异类型 | 例子 | 归因 | 处理 |
|---|---|---|---|
| 事实/数值 | Tm 差 1 ℃；Mn 差 5% | 数据/窗口/脚本 | 查原始数据与参数；不改规范，改流程 |
| 结构 | 少了误差分析；结论重复步骤 | 工作流不清 | 在工作流加检查项 |
| 图表 | 图注缺条件；四边框缺失 | 格式规范不清/未执行 | 加模板/自动检查 |
| 语言 | 口语化/绝对化 | 风格规范未约束 | 加禁用词/句式 |
| 格式 | 字体回退/表跨页 | 生成流程问题 | 三层字体/表头重复 |
| 合规 | 封面缺失 | 检查缺失 | 提交前 checklist |

## 6. 回归测试

每次修改规范后：

1. 重跑最近一次盲测任务（同输入、同范例）；
2. 只比较被修改的维度 + 是否引入新问题；
3. 通过后再跑另一任务；
4. 记录版本、日期、模型、结果；
5. 若新规则导致旧任务退步，回滚或限定适用范围。

## 8. 注意

- 盲测不是“让 AI 猜终稿”；终稿只是参照，规范才是目标。
- 若终稿本身有错（如本审计发现的图号/封面问题），不要以“像终稿”为通过标准；以规范和证据为准。
- 不得把终稿内容泄露到提示词或范例中；范例卡只写“可学/不可学”，不写具体数值。
- 记录“未通过”比记录“通过”更有价值；不要美化结果。
