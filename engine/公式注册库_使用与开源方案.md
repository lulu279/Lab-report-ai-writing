# Research DSC Engine v0.3：公式注册库和开源选型

日期：2026-10-26  
定位：在 v0.2 DSC 专项分析工具上，新增独立的**科学方法注册库**。本版本支持查阅方法、执行已获基础数值测试的基础公式；并**不代表** AI 已自主选用所有实验公式。

## 1. 设计原则

- **方法选择可智能，数值执行要确定**：AI 只能输出一个方法 ID、输入绑定和适用前提说明，不能提供可执行 Python 代码或任意字符串公式。
- **公式卡是对科学前提的记录**：每条方法包括公式、输入参数与单位、适用实验、局限、来源、执行状态、版本。公式本身的适用性仍需研究者确认。
- **先测后用**：仅 `tested_executor` 状态开放本地执行，其含义是有基础数值单元测试，不等于通过真实科研数据验证；`catalog_only` 不能执行。
- **新方法应先比对权威来源，再实现，最后测试**。不得默认把从 AI 生成的公式复制到执行模块。
- **现有 DSC 端到端流程保持不变**：原 DSC AI 峰/基线规划器仍只允许它原先支持的算法，不会因增加跨学科公式而自动获得通用分析能力。

## 2. 开源项目筛选

| 名称 | 作用 | 与本项目关系 | 许可或注意事项 |
|---|---|---|---|
| SciPy | 积分、插值、信号峰值、优化 | 建议核心数值后端；现有 v0.3 演示主要使用 NumPy trapezoid | https://docs.scipy.org/doc/scipy/ |
| pybaselines | 多算法背景/基线校正 | 未来加入 DSC/FTIR 基线候选，但不可不经验证就默认套用于热流峰 | BSD-3-Clause；https://pybaselines.readthedocs.io/ |

本版本**未复制或修改任何第三方仓库代码**，也未联网安装上述可选依赖。需要在正式引入时复核许可证、依赖和对应 API 版本。

## 3. 首批方法

实际机器可读目录：`method_registry/catalog.json`。

基础数值可执行的 9 项：
- `dsc_enthalpy_time_v1`：热流沿时间积分得到质量比焓变。
- `dsc_enthalpy_temperature_v1`：恒定扫描速率的温度积分；区分升温和降温的时间方向。
- `dsc_crystallinity_v1`：扣除冷结晶的结晶度估计；需要外部可核验参考熔融焓与填料质量分数。
- `tga_mass_loss_v1`：质量损失率。
- `tga_t_at_loss_v1`：指定质量损失百分比的首次阈值插值温度，例如 T5、T10。
- `uv_beer_lambert_v1`：用光程和摩尔吸光系数计算浓度。
- `ftir_transmittance_v1`：透过率转吸光度。
- `gpc_mass_moments_v1`：真正质量分数下的 Mn、Mw、Đ；不能直接将未校正色谱峰面积当质量分数。
- `nmr_integral_ratio_v1`：氢数归一化的峰积分比；不等于任何 NMR 谱都可用于定量分析。

仅登记、不可执行的 4 项：
- DSC Tg 中点判读；
- DSC 重叠峰分解；
- FTIR AsLS 基线；
- TGA DTG 峰值与分离。

**注意**：注册库并非实验方法学的权威手册。每个公式都有适用域和输入约束，特别是参考焓、积分窗口、基线方法、校准和测量协议，必须结合仪器原始文件、讲义及原始文献确认。

## 4. 本地使用方法

在项目根目录：

```powershell
python -m pytest -q
python -m research_engine.formula_cli list
python -m research_engine.formula_cli list --experiment DSC
python -m research_engine.formula_cli show dsc_enthalpy_time_v1
python -m research_engine.formula_cli run dsc_enthalpy_time_v1 method_registry/example_dsc_time.json
python -m research_engine.formula_cli run dsc_crystallinity_v1 method_registry/example_dsc_crystallinity.json
python -m research_engine.formula_cli run tga_t_at_loss_v1 method_registry/example_tga_T5.json
python -m research_engine.formula_cli run gpc_mass_moments_v1 method_registry/example_gpc.json
python -m streamlit run app.py
```

在网页底部新增 **科学公式注册库**，可以查看公式卡、输入 JSON，并仅对已实现的基础方法进行计算演示。

**这些 JSON 示例全部是为测试人工编造的数值，与 DSC 历史报告或实际仪器数据没有关联。**

## 5. 模块接口

```python
from research_engine.formula_registry import public_catalog, execute_formula

methods = public_catalog('DSC')
result = execute_formula('dsc_enthalpy_time_v1', {
    'time_s':[0,5,10],
    'heat_flow_mw':[0,2,0],
    'baseline_mw':[0,0,0],
    'sample_mass_mg':2
})
# 本示例返回带符号 5.0 J/g；只是已知数值的基础测试。
```

`execute_formula` 只执行静态允许列表中的已实现方法。其返回值包括 `method_id`、方法版本、输入参数、科学前提、结果、单位和未审核状态。缺失参数、多余参数、非数值、NaN、无效单位范畴、非单调扫描或超过适用域会触发错误，而不是悄然修正。

## 6. 下一版 AI 自主选方法的完整流程

1. **解析数据与实验目标**：确定实验类别、原始数据列与单位、样品、分段、研究问题；不能从图像猜测测量单位。
2. **召回候选方法**：使用注册库的实验类型、所需数据和适用前提筛选 2–5 个候选方法；未实现方法仅可作为“推荐新增”，不得执行。
3. **模型提出结构化方案**：返回方法 ID、输入数据字段映射、选择理由、替代方案和需要补充的校准信息。
4. **本地验证**：检查方法是否已实现、输入参数与单位是否正确、必需前提是否得到证据支持、是否存在异常数据。
5. **人工审核关键方法**：首次使用的新分析方法、未核验的参考常数、物理机制假设需审核；不能因为模型评分高就自动通过。
6. **固定代码执行**：记录数据哈希、方法 ID 和版本、输入值和 QA 标志。计算器不接受模型提供的新 Python 源码。
7. **比较模型及稳健性**：不同基线、拟合窗口、模型假设的敏感度，而不是只输出唯一结果。
8. **科学文档生成**：生成图像、DOCX 草稿和待核验清单，并允许研究者确认或修订。

## 7. 当前质量验证与限制

- 新增 12 项测试，连同 v0.2 原有 17 项离线测试，共 29 项通过。
- 测试覆盖单位换算型基础公式、升降温时间积分、TGA 阈值、GPC 质量分数、异常输入和方法白名单拒绝。
- 仍没有真实 DSC 原始数据，因此**不存在科学实测准确性的评估**。
- OpenAI/DeepSeek API 没有在本版本实际调用，不能声称 AI 自主选方法的成功率。
- Streamlit UI 新版功能需要在目标 Windows 计算机上运行验证；本地仅做 Python 静态编译和后端单元测试。
- 新增跨实验公式仅作为独立计算器，没有被添加进 v0.2 DSC 峰检测流水线；v0.2 已实现的 DSC 数据处理方式仍不变。
- 目前没有完整的量纲引擎；输入单位依照每个方法的静态契约，未来建议 Pint 0.25.x 锁定版本并补回归测试。

## 8. 建议的下一阶段：v0.4

只选 DSC 首先做真数据：用真实仪器导出文件与可靠标定信息建立独立真实案例；复核扫描程序与端点基线，再将 DSC 公式注册库与 AI 峰事件规划器统一。随后新增一套 TGA 正式数据解析器，通过第二类实验检验可迁移性。
