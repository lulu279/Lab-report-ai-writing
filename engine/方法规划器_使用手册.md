# Research DSC Engine v0.2 — AI 方法规划器使用手册

## 1. 与 v0.1 的区别

- v0.1 **没有固定接入任何模型**；其 OpenAI SDK 接口只用于可选的讨论草稿，未实际调用过外部 API。
- v0.2 增加了「AI 规划实验数据处理方法」：模型依据样品信息、扫描方向、信号摘要，提出候选峰、温度窗口、基线方法，并说明理由与置信度。
- **v0.2 仍不是让 AI 随意执行自己写的公式**。模型只能引用算法登记表中已实现且通过测试的方法；未知方法必须推迟执行，先人工评估及开发测试。
- v0.2 已实现方法包括：**DSC 峰面积时间积分**，使用两种端点基线（线性、常数）。`Tg` 中点法已登记但尚未实现；TGA、FTIR 等同样没有实现。
- 只有用户点击调用，且设置 API Key，才会把数据摘要发送到外部模型；不会默认发送完整原始数据。

## 2. 选择哪家 AI？

采用 OpenAI Python SDK 的 **OpenAI-compatible** Chat Completions 协议。没有预设模型，无密钥则不调用任何 AI。

环境变量：
- `AI_API_KEY`：API 密钥；亦支持 `OPENAI_API_KEY`。
- `AI_BASE_URL`：自建或兼容接口的完整 base URL。留空时使用 OpenAI SDK 默认接口。
- `--model` 或界面中的「模型 ID」：你自己的 API 账户实际可以调用的模型 ID。

可以接入支持兼容协议的服务，但**兼容性需要逐一验证**；订阅某个聊天产品的会员不自动等于拥有其 API 使用权。使用非官方 endpoint 前，必须检查 URL 和数据分享许可。不要在聊天中直接发送密钥。

## 3. 本地操作步骤（Windows PowerShell）

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-ai.txt
python -m pytest -q
$env:AI_API_KEY="仅在本机设置你自己的API密钥"
# 第三方兼容端点可设置（务必替换成实际文档规定的合法地址）
# $env:AI_BASE_URL="https://YOUR_PROVIDER_BASE_URL/v1"
python -m streamlit run app.py
```

网页界面中上传标准化 CSV 和 JSON/YAML 元数据。**元数据允许没有 `windows`**；但必须声明样品质量、热流方向、单位等。然后：

1. 输入实际可用的模型 ID；如非 SDK 默认接口，填入可信的 API Base URL。
2. 点击 `① 让真实 AI 提议分析方法`。
3. 阅读每个事件的相态、区间、基线、证据、置信度及本地预检查警告。
4. 对方案中的问题进行人工确认，勾选同意。
5. 点击 `③ 确认并执行`，系统用经过验证的方法代码执行，且生成 SHA-256 追踪信息。
6. 下载 ZIP，查看 `results.json`、`validation.json`、`manifest.json`、`inputs/ai_plan.json` 与 DOCX 草稿。

若模型提出了不支持的计算方法，系统会拒绝该方法，不能伪装成成功。对于重叠峰、不明确的阶段或 Tg，模型应列为 `deferred_events`。

## 4. 独立命令行规划（不执行计算）

```powershell
python -m research_engine.plan_cli --data examples/synthetic_dsc.csv --config examples/synthetic_metadata.json --model "你实际可用的模型ID" --out ai_plan_preview.json
```

它会写出：
- `ai_plan_preview.json`：原始 AI 建议、本地校验、发送给模型的摘要与模型元信息。
- `ai_plan_preview_suggested_config.json`：经过 schema 校验的计算配置。

**注意：CLI 规划不会自动执行；请先查看并修改配置，再使用旧版数据计算 CLI**：

```powershell
python -m research_engine.cli --data examples/synthetic_dsc.csv --config ai_plan_preview_suggested_config.json --out runs
```

GUI 审核路径会额外将确认过的 AI 计划保存到此次运行的 `inputs/ai_plan.json` 中。上面独立 CLI 则不会自动宣称用户已确认 AI 方案。

## 5. AI 选择什么、程序验证什么？

| 对象 | AI 规划 | Python 校验 / 执行 | 人工负责 |
|---|---|---|---|
| 实验阶段 | 依据明示标签判断升温/降温候选 | 检查数据实际温度变化方向 | 纠正分段和仪器工况 |
| 事件类型 | 熔融、结晶、升温冷结晶 | 方向、积分符号、峰形边界检查 | 检查重叠峰与归属 |
| 数学方法 | 在已批准算法目录中选择，说明适用前提 | 按确定性代码计算，不执行模型生成代码 | 批准新的方法与参考常数 |
| 基线与积分区间 | 提出两种基线和候选窗口 | 检查数据点数、范围、敏感度 | 调整难以自动识别的峰区 |
| 结晶度 | 判断是否可用、提示未评估冷结晶 | 应用正确焓项和已登记参考量 | 核实物性参考及材料状态 |
| 结果解释 | 提出物理解释与局限 | 核对数字来源与方法 | 判断论断是否受到数据支持 |

## 6. 多实验扩展接口建议

每个新分析插件至少声明：

```yaml
experiment_type: TGA
method_id: tga_tangent_onset_v1
status: NOT_IMPLEMENTED
expected_inputs: [temperature_c, mass_percent]
outputs: [onset_temperature_c]
required_metadata: [atmosphere, heating_rate]
equation_reference: ''
applicability: ''
provenance_required: true
validation_tests: []
```

AI 可以根据研究目标选择适当算法，也可以提出新算法的候选说明；**只有方法通过物理量纲校验、独立计算示例、边界情况测试并经人工批准后，才可被登记为可执行方法**。在插件未建成之前，工作流应标记 `NOT_IMPLEMENTED` 而不是继续模拟输出。

## 7. 测试覆盖与已知缺口

- 17 项自动化离线测试，包含：模拟模型响应方案的 schema 验证、禁止执行未知方法、拒绝编造样品、窗口越界拒绝、基线选择、运行追踪；以及旧版数值与 DOCX 测试。
- 离线测试 **不证明模型能正确判断科学方法**；尚未进行任何真实 OpenAI、DeepSeek 或其他模型的 API 调用。
- 当前未实现完整真实仪器 TXT 解析、自动仪器校准、Tg、重叠峰分离、跨实验公式规划和原始科研数据的盲测。
- 基线变化 >25% 的拒绝阈值与 15–25% 的警告阈值是工程启发式，并非所有 DSC 仪器的规范阈值。
- Streamlit 未在本运行环境安装，网页代码经过静态检查，但必须在你的本地环境实际启动确认。
- 课程实验若禁止 AI 独立代写，必须限制为被允许的数据处理、草稿辅助和人工作业审阅。
